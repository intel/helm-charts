The manager serves an admission webhook, so it runs {{ .Values.replicaCount }} replica(s) for HA.
Leader election keeps one replica active; the others are hot standbys that also serve the webhook.

High availability guidance:
  * Set replicaCount to min(nodes, 3). More replicas than nodes buys no extra
    availability and just costs their resources.
  * Replicas are spread across nodes and prefer control-plane nodes via a SOFT
    default affinity (override .Values.affinity to replace it).
  * The manager does NOT self-scale. Have your deploy tooling pass
    --set replicaCount=<min(nodes,3)> if you want it to track the node count.
{{- if le (int .Values.replicaCount) 1 }}

  NOTE: replicaCount is {{ .Values.replicaCount }} — no PodDisruptionBudget is rendered (a
  minAvailable:1 PDB on a single replica would block node drains). Raise
  replicaCount for HA once you have more than one schedulable node.
{{- end }}
